# TOKEN Engineering Lessons

Each material incident becomes a prevention rule and, when practical, a permanent regression gate.

## L-001 — Stale local HEAD

- **Incident:** Local work began from a branch behind the remote canonical HEAD.
- **Root cause:** Local branch state was treated as canonical truth without a fresh remote comparison.
- **Why gate missed it:** The earlier workflow did not make remote-SHA equality a mandatory pre-mutation check.
- **Permanent prevention:** Fetch the canonical remote and bind every mutation worktree to the exact fresh remote SHA.
- **Regression test:** Qualification records both worktree HEAD and `origin/token-v1-core` and blocks on mismatch.

## L-002 — Public local-path leakage

- **Incident:** Internal absolute paths appeared in material that could be mistaken for public documentation.
- **Root cause:** Public/private document boundaries were implicit.
- **Why gate missed it:** There was no complete classification plus privacy audit.
- **Permanent prevention:** Classify every tracked path and audit public candidates for POSIX/Windows user paths.
- **Regression test:** Public-audit negative fixtures include local user-path patterns.

## L-003 — Real author email risk

- **Incident:** Repository history or release material can expose a real author email.
- **Root cause:** Provenance and privacy policy did not explicitly constrain identity metadata.
- **Why gate missed it:** Source tests do not inspect privacy-sensitive release metadata.
- **Permanent prevention:** Public artifacts prohibit raw non-noreply email addresses and deterministic manifests exclude author metadata.
- **Regression test:** Public-audit tests reject raw non-noreply email addresses.

## L-004 — Source-versus-artifact testing

- **Incident:** Passing source-tree tests alone could not prove that the released runtime bytes matched canonical source.
- **Root cause:** Artifact equivalence was not a first-class gate.
- **Why gate missed it:** Tests exercised source imports rather than a generated public candidate.
- **Permanent prevention:** Deterministic export and runtime tree digests are mandatory release gates.
- **Regression test:** Release-pipeline tests compare canonical and candidate runtime digests byte-for-byte.

## L-005 — Token savings with quality regression

- **Incident:** A live evaluation found a workload class where token reduction was not sufficient evidence of acceptable quality.
- **Root cause:** Optimization eligibility was broader than the evidence justified.
- **Why gate missed it:** Token-savings metrics alone could mask semantic regression.
- **Permanent prevention:** Quality is a release invariant; risky structured decision contexts bypass unchanged.
- **Regression test:** Frozen behavior tests require protected fidelity, recovery correctness, and conservative bypass policy.

## L-006 — Manual public sanitization risk

- **Incident:** Manual copying and cleanup can silently omit a private file or leave sensitive content in a public payload.
- **Root cause:** Sanitization depended on operator memory.
- **Why gate missed it:** No deterministic file classifier or fail-closed audit existed.
- **Permanent prevention:** Generate public candidates from explicit classification, reject unclassified paths, audit all public bytes, and compare deterministic double exports.
- **Regression test:** Release-pipeline tests reject unclassified files and require two exports to be byte-identical.

## L-007 — Generated bytecode polluted source digest

- **Incident:** Runtime digest comparison differed even though exported source bytes were unchanged.
- **Root cause:** Recursive digesting included generated bytecode/cache files that are not release source artifacts.
- **Why gate missed it:** Earlier digest logic did not distinguish source artifacts from interpreter-generated files.
- **Permanent prevention:** Runtime tree digests exclude bytecode and cache directories deterministically.
- **Regression test:** Release-pipeline runtime-equivalence tests run after test imports create normal cache artifacts.

## L-008 — Import tests missed direct-script execution

- **Incident:** Release modules imported successfully in unit tests, but the documented direct CLI command failed before argument parsing.
- **Root cause:** Module-import and direct-script execution have different package paths.
- **Why gate missed it:** Tests exercised Python imports but not the exact operator command.
- **Permanent prevention:** Release/audit tools support both package import and direct-script execution.
- **Regression test:** A subprocess regression invokes the documented release and audit CLI paths directly.

## L-009 — Public README referenced excluded private material

- **Incident:** A public-candidate README linked to documents intentionally excluded from the public export and used a private canonical branch in its CI badge.
- **Root cause:** File classification validated payload membership but not public navigation assumptions.
- **Why gate missed it:** Secret/privacy audit does not detect harmless-looking broken relative links or wrong public branch names.
- **Permanent prevention:** Public-facing links name only exported documents and the public governance branch.
- **Regression test:** Public-ready contract tests require the public `main` badge and reject links to private-only document paths.
